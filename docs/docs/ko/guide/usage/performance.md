# 성능

Text Motion은 제목, 레이블, 온보딩 문구, 짧은 제품 설명처럼 중요한 UI 텍스트를 대상으로 합니다. 성능은 애니메이션 단위 수, 효과, 동시에 표시하는 컴포넌트 수, 기기와 재생 방식에 따라 달라집니다. 이 문서는 특정 FPS나 모든 환경에 통용되는 안전한 글자 수를 보장하지 않습니다.

## 애니메이션 단위 선택

`nativeText()`는 애니메이션 토큰마다 내부 `Text`와 애니메이션 `View` 컨테이너를 사용합니다. 정적 토큰은 일반 텍스트로 남습니다. 이 구조로 토큰 변형을 표시할 수 있지만, 글자 단위 분할은 단어 단위보다 훨씬 많은 애니메이션 단위를 만들 수 있습니다.

- 단어 단위 모션으로 의도가 전달된다면 `words()`를 우선 사용하세요.
- 짧은 글자 단위 표현에는 `graphemes()`나 `typewriter()`를 사용하고, 더 큰 작업량은 측정하세요.
- 레시피 컴포넌트는 렌더 함수 밖에 만드세요. 재시작만을 위해 반복해서 언마운트하기보다 controls로 기존 컴포넌트를 다시 재생하세요.
- 공유 controls는 실제 마운트할 행 수로 검사하세요. 명령 하나가 연결된 모든 컴포넌트에 전달됩니다.
- 실제 렌더링된 줄을 움직여야 한다면 `overlayText()`를 사용하세요. 네이티브 텍스트를 측정하고 줄마다 잘린 문단 복사본을 렌더링하므로, 모션 단위가 적다는 이유만으로 더 빠르다고 판단할 수는 없습니다.

레이아웃의 차이는 [렌더러](../../api/renderers.md), 명령과 진행률 제어는 [재생 제어](./playback.md)를 참고하세요.

## 예제 앱으로 프로파일링

측정할 플랫폼에서 저장소의 예제 앱을 실행하세요. 명령은 [예제](./examples.md)에 있습니다.

**Playback → Renderer Performance**에서 단어·글자 작업량, Typewriter, 반복 재생, 공유 행, 외부 진행률 사례를 확인할 수 있습니다. **Playback → Controls Stress**는 명령을 여러 컴포넌트에 전달하는 추가 사례입니다. **Layout → Line Reveal**과 **Layout → Line Layout Probe**에서는 너비, 정렬, 글꼴 배율, 명시적 줄바꿈과 언어별 표시를 확인할 수 있습니다.

사례의 `normal`, `caution`, `stress` 표시는 프로브의 작업량 구분입니다. 측정된 성능 등급이나 지원하는 토큰 수 한도가 아닙니다. UI의 토큰·노드 수 추정치도 진단용이며 공개 구현 계약이 아닙니다.

React Native Perf Monitor, Xcode Instruments, Android Studio Profiler, Flashlight 같은 실제 FPS·프로파일링 도구를 사용하세요. 측정과 함께 기기·OS, 플랫폼, 빌드 모드, 텍스트·splitter, 효과, 컴포넌트·모션 단위 수, 재생 방식, 눈에 보이는 끊김을 기록하세요. 개발 모드와 시뮬레이터의 결과는 그 조건을 명시해야 합니다.

## 측정 근거 표기

| 상태 | 필요한 근거 |
| --- | --- |
| `measured` | 같은 사례 유형에 대해 iOS와 Android 근거가 모두 있습니다. |
| `provisional` | 한 플랫폼만 확인했거나 시뮬레이터·에뮬레이터·개발 모드의 근거만 있습니다. |
| `unknown` | 해당 사례 유형을 측정하지 않았습니다. |

이 사이트는 플랫폼별 근거가 함께 제공되지 않는 작업량을 측정 완료로 주장하지 않습니다.

일반적인 제목과 레이블이 부드럽다면 기본 렌더러를 유지하고 무거운 텍스트의 경계를 안내하세요. 일반적인 작업량부터 끊긴다면 효과를 추가하기 전에 렌더러 비용을 조사하세요. 글자 단위 스트레스 사례가 실패했다는 사실만으로 일반적인 단어 단위 제목에도 다른 렌더러가 필요하다고 판단할 수는 없습니다.

## 프레임과 레이아웃을 함께 검증

`nativeText()`는 토큰별 변형을 위해 단일 `Text`의 정확한 글자 조형과 줄바꿈을 일부 포기합니다. `overlayText()`는 네이티브가 렌더링한 줄을 따르지만 앱의 글꼴, 배율, 너비, 정렬, 문자 체계에서도 확인해야 합니다. FPS만으로 줄바꿈, 접근성 읽기 순서, 모션 감소 동작까지 검증할 수는 없습니다. [문자 분할](./segmentation.md)과 [접근성](./accessibility.md)을 참고하세요.
